# 닉네임·신고·제재 백엔드 협의 사항 (FE 시연용 UI 후속 단계)

이 문서는 **새 API를 구현했다는 의미가 아닙니다.** 현재 공개 README에서 확인되는 닉네임 변경은 `PATCH /api/v1/users/me`뿐입니다. 백엔드를 허락 없이 변경하지 않았습니다.

## 필요 동작 (엔드포인트는 BE 팀과 합의 후 확정)

1. 닉네임 중복/정책 검사: 로그인 사용자 닉네임 후보를 검사하며 사용 가능/사용 불가를 구분. 이때 **금칙어 내용이나 금칙어 목록을 응답에 포함하지 않음**. 후보명 조회를 악용하지 못하도록 인증, 빈도 제한, 동일한 거부 메시지, 감사 로그 적용.
2. 닉네임 변경: `PATCH /api/v1/users/me`에서도 **동일한 정책과 유니크 제약을 최종 확인**. 별도 중복 확인과 저장 사이에 동일 닉네임이 선점될 가능성(TOCTOU)을 DB 고유 제약으로 차단. 기존 2~20자 명세와 새 정책의 충돌을 BE와 조정.
3. 닉네임 정책: 한글만 또는 영어만 허용, 숫자는 각각 혼합 가능, 한글+영문 혼합 및 공백·특수문자 금지. 한글/한글+숫자 및 숫자만 2~6자, 영어/영어+숫자 2~12자. 예약어 `이용제한` 불허. 앱에서 비속어/정치·성적 표현 목록을 내려받지 않으며 검사는 **서버에서** 수행. 정당한 정책 집행을 위해 맥락·오탐에 대한 수동 검토와 이의 신청 절차 필요.
4. 신고 접수: 신고자의 인증과 대상 사용자 ID로 접수; 자기 신고 제한, 중복/악용 방지, 접수 결과 ID 반환. 대상 닉네임은 당시 값의 스냅샷과 함께 관리자 전용 저장소에 보관하고 일반 사용자 조회에는 제공하지 않음. 개인정보 보유 기간·접근 권한 규정 필요.
5. 관리자 조회·판정: 관리자 권한을 **서버에서 검증**하는 신고 대기 목록/상세/기각/제재 API와 감사 로그 필요. 신고 접수만으로 자동 제재하지 말고 담당자 확정 후 처리.
6. 제재: 확정 시 서버에서 닉네임을 `이용제한`으로 변경하고, 기존 이름을 서버 관리용 비공개 이력에 보관. 사용자의 세션에서도 강제 변경 상태를 확인해 앱 사용을 제한하며 정해진 확인 문구를 입력하고 새 닉네임으로 변경해야 해제. 중간 종료·재진입 시 서버 제재 상태를 기준으로 처음부터 표시.
7. 다른 클라이언트 동기화: 지도/리그/친구/추천 친구에서 제재된 사용자 닉네임이 재조회 즉시 갱신돼야 함. 개인 브라우저 `localStorage`만으로는 불가능.

## 현재 FE 패치의 제한

- 중복 확인 버튼은 현재 브라우저에서 포함된 **목 사용자 명단**만 검사합니다. 녹색 문구에는 시연용이라는 주석이 명시되며, 최종 변경은 기존 `PATCH` 응답에 따릅니다.
- 신고 버튼은 동일 브라우저 `ddorang:demo-nickname-reports`에 데모 데이터를 기록합니다. 실제 신고 접수, 관리자 조회, 데이터베이스 보관은 지원하지 않습니다.
- 서버의 `GET /api/v1/users/me`가 닉네임 `이용제한`을 반환하는 경우에만 FE에서 차단 UI를 보여 줍니다. FE는 계정을 강제로 제재하지 않습니다.
- 새로 만든 팝업에만 테마 기반 75% 반투명 표면을 적용했습니다. 팀원 담당 공통 모달을 무단 변경하지 않았습니다.
